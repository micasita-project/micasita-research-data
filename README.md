# MiCasita — research data and code

Data, code and trained model supporting the paper *XGBoost-based travel-time correction in a hybrid expert system for commute-aware housing recommendation in Metropolitan Lima* (Astuyauri-Calderon, Calderon-Huaman, Castro-Veramendi; Universidad Peruana de Ciencias Aplicadas, Lima, Peru).

MiCasita is a mobile application that ranks rental homes in Metropolitan Lima by the commute to the user's workplace. A routing engine (OSRM) estimates a free-flow travel time, an XGBoost regressor corrects it to a traffic-aware time, and an explicit scoring function (`match_score`, 0–100) combines the corrected time with budget, distance and floor area.

Corresponding author: u202213076@upc.edu.pe

## Reproducing the results

Python 3.11 and `pip install -r requirements.txt`. Run everything from this folder.

```bash
# Correction model (model-performance results of the paper): retrains and prints the cross-validated metrics.
# The saved artefacts are byte-identical to the ones in ml_pipeline/model/.
PYTHONPATH=. python ml_pipeline/train_travel_time.py

# Ranking evaluation: NDCG@5 of the model and of the price-only and OSRM-only baselines
# (mean 0.866 / 0.595 / 0.736).
python scripts/compute_ndcg5.py
```

`collect_traffic_data.py` needs a TomTom API key, running OSRM instances (one per transport profile) and the housing catalogue; `run_evaluation.py` needs the application database; `benchmark_api_latency.py` needs a running backend. They are included for transparency and are not needed to reproduce the tables above.

## Data description

### `travel_time_dataset.csv`

One row per trip (origin = home, destination = workplace) at a given mode and time slot.

| Column | Description |
|---|---|
| `pair_key` | Unique key of the trip (rounded coordinates, mode, slot) |
| `workplace_id`, `workplace_nombre`, `work_lat`, `work_lon` | Workplace (one of ten hubs) |
| `property_id`, `prop_ids`, `prop_lat`, `prop_lon`, `prop_district` | Origin location; `prop_ids` lists every listing that shares the coordinates |
| `modo` | `driving`, `cycling` or `walking` |
| `franja`, `depart_at`, `dia_semana`, `hora` | Time slot (`punta_manana` 07:00, `valle` 13:00, `punta_tarde` 18:00), departure timestamp, weekday (0 = Monday; all trips use 1 = Tuesday) and hour |
| `osrm_dist_km`, `osrm_min`, `osrm_status` | OSRM route distance and free-flow duration (model input) |
| `work_dist_centro_km`, `prop_dist_centro_km`, `hacia_el_centro` | Distance of workplace and origin to the city centre; 1 if the workplace is closer to the centre than the origin |
| `tt_dist_km`, `tt_min`, `tt_sin_trafico_min`, `tt_historico_min`, `tt_demora_min`, `tt_status` | TomTom route distance and traffic-aware duration (model target `tt_min`), free-flow, historical and delay times |

Driving trips cover three time slots (3,000 trips per slot); cycling and walking cover only the midday slot (3,000 trips each). The training script removes the 1% most extreme `tt_min` per mode (150 trips), leaving 14,850.

### `NDCG5_scenarios_anonymised.xlsx`

Sheet `Escenarios_Evaluacion`: 20 scenarios, each with the 10 candidate homes produced by the model. Participants are identified by codes (P01–P20) equal to the scenario number. Relevance is derived from the human ranking (1.0 for ranks 1–2, 0.5 for ranks 3–5, 0 for ranks 6–10). The columns *Ranking por PRECIO* and *Ranking por TIEMPO OSRM crudo* are the two baselines; ties are broken with the model order.

## Privacy and exclusions

- Participants are identified only by codes. Names and identity-document numbers recorded to organise the sessions are not included.
- The housing listings were collected from a commercial portal and are not redistributed here; they are available from the authors on reasonable request, subject to the portal's terms of use.
- No credentials or API keys are included.
- The usability (SUS) responses are not part of this release yet.
